# Hub — Netlist Error resolved after silkscreen-image addition

## Confirmed cause and fix

The DRC Netlist Error was **25 stale J3 descriptive properties on the PCB**, not an electrical,
routing, footprint or image error. The schematic already held the corrected KCD4 values; the PCB
still had older row-spacing/pitch, supplier, material, dimensional and rating metadata.

The user opened the Import Changes comparison without applying it. The agent read the complete
dialog and verified all 25 entries were **Update Property / J3**, with no footprint, pad, route,
net, placement or image changes. A complete project backup was made before applying anything.
The user then unchecked **Also update track's net**, applied the reviewed properties and saved.

**Fresh strict PCB DRC: empty. Fresh schematic ERC: true, detailed findings empty.** The previous
generic synchronization finding is now resolved; older review reports describing it are historical.

## Reusable lesson

A generic Netlist Error can be caused entirely by descriptive attributes. Establish the exact ECO
differences first; never infer the cause merely because the pin map matches. A completely reviewed,
metadata-only ECO can be applied safely with full backups and before/after preservation checks.
That is different from blindly applying an import or standardizing a custom footprint back to a
catalog device. Similarly, a visible raster image in the PCB editor is not evidence that a normal
silkscreen Gerber contains it. Inspect the actual output.
